## 2. ประเด็นที่ต้องตัดสินใจก่อน: ทริปจริงอยู่ห่างแค่ 5 วัน

ทริปนำร่องออกเดินทาง **เสาร์ 10 ต.ค. 2026** วันนี้คือ **จันทร์ 5 ต.ค.**

ถ้าทำตามลำดับ Phase 1 → 7 ตรง ๆ ตอนออกทริปจะมีแค่ระบบ login กับ Trip CRUD
ซึ่งยังใช้ทำอะไรระหว่างเดินทางไม่ได้ และจะพลาดโอกาสทดสอบกับการใช้งานจริงซึ่งมีค่ามากที่สุด

**ข้อเสนอ:** ตัดชิ้นแนวตั้งจาก Phase 1, 3 และ 4 มาทำก่อนเป็นรุ่น `v0.1 Trip-Ready`
ให้จดค่าใช้จ่ายและโน้ตได้จริงบนมือถือทันวันที่ 9 ต.ค. แล้วค่อยกลับมาทำส่วนที่เหลือตามลำดับ

สิ่งที่เลื่อนออกไปคือ Phase 2 (วางแผน) เพราะแผนของทริปนี้มีอยู่ในหัวแล้ว
แต่สิ่งที่จดระหว่างทริปถ้าไม่ได้จดจะหายไปเลย

ถ้าไม่ต้องการใช้กับทริปนี้ ให้ใช้ลำดับเดิมใน §5 ได้ทันที เอกสารอื่นไม่ต้องแก้

ขอบเขตแคบโดยตั้งใจ ทุกอย่างที่ไม่อยู่ในตารางนี้ถือว่ายังไม่ทำ

**สถานะ 6 ต.ค.:** ทำครบทุกข้อในตารางแล้ว (F1.1–F1.4, F3.1–F3.4, Journal แบบย่อ, Timeline แบบง่าย)
ทดสอบบนมือถือจริงทุกตัว เร็วกว่าแผนหนึ่งวัน เหลือ deploy production และสร้างทริปจริง (งานวันศุกร์)

**ตัดออกจาก v0.1 โดยเจตนา**

- อัปโหลดรูปและใบเสร็จ: ต้องตั้ง storage และมีจุดพังเยอะ ระหว่างทริปถ่ายเก็บในเครื่องไว้ก่อน แล้วแนบย้อนหลังเมื่อ feature เสร็จ
- Itinerary, Places, แผนที่
- เชิญเพื่อนเข้าระบบ: คนเดียวจดให้ทั้งสองคน
- Offline queue: มีแค่การกันรายการซ้ำด้วย `clientId`

**ลำดับความสำคัญถ้าเวลาไม่พอ** ตัดจากล่างขึ้นบน

1. Auth + สร้างทริป
2. จดรายจ่าย + ดูยอดรวมและงบคงเหลือ
3. Deploy ให้เปิดจากมือถือได้
4. Settlement
5. จดโน้ต
6. Timeline

ถ้าถึงวันศุกร์แล้วมีแค่ข้อ 1–3 ก็ถือว่าใช้ได้ ไปทริปได้

**ความเสี่ยง**

| ความเสี่ยง                  | รับมือ                                                             |
| --------------------------- | ------------------------------------------------------------------ |
| Deploy ติดปัญหาในวันสุดท้าย | ลอง deploy หน้า health check ตั้งแต่วันอังคาร ไม่รอวันศุกร์        |
| ติดกับการเรียนรู้ Prisma    | schema และ migration ทำวันแรก query ซับซ้อนใช้ raw SQL ที่ถนัด     |
| Bug ระหว่างทริปทำข้อมูลหาย  | เปิด backup ฐานข้อมูลก่อนออกเดินทาง ไม่ deploy โค้ดใหม่ระหว่างทริป |
| ทำไม่ทัน                    | ลำดับตัดด้านบน และสำรองด้วยการจดในโน้ตมือถือ แล้วคีย์ย้อนหลัง      |

## 4. ลำดับการพัฒนาภายใน feature

ทุก feature เดินตามลำดับเดียวกัน

```
1. Prisma schema + migration     (ถ้ามีการเปลี่ยนแปลง)
2. Zod schema                    กำหนด input
3. Repository                    query
4. Service                       กฎและการคำนวณ
5. Controller + Route            ต่อ middleware
6. Test                          service และ API
7. Frontend api + hooks
8. Component + Page              ครบสี่สถานะ
9. ทดสอบบนจอมือถือ
10. อัปเดตเอกสาร
```

ทำ backend ของ feature ให้จบและทดสอบผ่านก่อนเริ่ม frontend ของ feature เดียวกัน

## 5. ลำดับเดิมตาม Phase (ทางเลือก)

ใช้เมื่อไม่ต้องการให้ทันทริป 10 ต.ค.

| ลำดับ | Phase         | ต้องเสร็จก่อนเพราะ                                         |
| ----- | ------------- | ---------------------------------------------------------- |
| 1     | Foundation    | ทุกอย่างต้องใช้ auth และ trip                              |
| 2     | Trip Planning | สร้าง members และ places ที่ phase ถัดไปอ้างถึง            |
| 3     | Expense       | ต้องมี members เป็นคนจ่าย                                  |
| 4     | Journal       | ต้องมี places และ expenses เพื่อผูกเข้า entry และ timeline |
| 5     | Map & APIs    | ต้องมีข้อมูลพิกัดจาก places และ entries                    |
| 6     | Analytics     | ต้องมีข้อมูลจริงให้วิเคราะห์                               |
| 7     | Polish        | เก็บงานทั้งระบบ                                            |

## 6. Definition of Done

Feature หนึ่งถือว่าเสร็จเมื่อครบทุกข้อ

- [ ] ทำงานตามเกณฑ์ใน FEATURES.md
- [ ] API ตรงกับ API.md หรืออัปเดตเอกสารแล้ว
- [ ] ผ่าน Security Checklist ใน AGENTS.md
- [ ] มี test ของ service ที่มี logic และ API หลัก และผ่านทั้งหมด
- [ ] lint ผ่าน ไม่มี warning ใหม่
- [ ] UI มี Loading / Empty / Error state
- [ ] ทดสอบบนจอ 375px แล้ว
- [ ] ไม่มีค่า hard-code และไม่มี secret ในโค้ด
- [ ] อัปเดตสถานะใน FEATURES.md และเอกสารนี้
- [ ] commit แยกตาม feature

Security, error handling และ responsive อยู่ในเกณฑ์นี้ทุก feature ตั้งแต่ต้น
Phase 7 เป็นการเก็บรายละเอียดเพิ่ม ไม่ใช่จุดเริ่มทำเรื่องเหล่านี้
