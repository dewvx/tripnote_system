# Features

รายการ feature แยกตาม phase พร้อมเกณฑ์ว่า "เสร็จ" หน้าตาเป็นอย่างไร
สถานะ: ⬜ ยังไม่เริ่ม · 🟡 กำลังทำ · ✅ เสร็จ

ลำดับการลงมือทำจริงดูที่ `ROADMAP.md` เอกสารนี้อธิบายว่าแต่ละอย่าง **คืออะไร**

---

## หลัก UX ที่ใช้กับทุก feature

1. **จอ 375px ก่อน** ทุกหน้าต้องใช้ได้ด้วยมือเดียว
2. **ถามให้น้อยที่สุด** field บังคับมีเท่าที่จำเป็น ที่เหลือมีค่าเริ่มต้นหรือเติมทีหลังได้
3. **จำค่าล่าสุด** หมวดและคนจ่ายที่ใช้ครั้งก่อนถูกเลือกไว้ให้
4. **เวลาคือ "ตอนนี้" เสมอ** เว้นแต่ผู้ใช้จะแก้
5. **ทุกหน้ามีสี่สถานะ:** กำลังโหลด (skeleton), ว่าง (พร้อมปุ่มเริ่มต้น), ผิดพลาด (พร้อมปุ่มลองใหม่), มีข้อมูล
6. **บันทึกแล้วเห็นผลทันที** ใช้ optimistic update กับรายการที่เพิ่ม
7. **การลบต้องยืนยัน** และข้อความต้องบอกชัดว่าอะไรจะหายไป
8. **ข้อความผิดพลาดเป็นภาษาคน** บอกว่าเกิดอะไรและทำอะไรต่อได้

## Phase 1 — Foundation

### F1.1 Project Setup ✅

- โครง `client/` และ `server/` ตาม ARCHITECTURE.md
- ESLint, Prettier, `.env.example`, Docker Compose สำหรับ MySQL
- `GET /api/health` ตอบได้ และหน้าแรกของ client เรียกถึง
- `docs/DEVELOPMENT.md` อธิบายวิธีรันตั้งแต่ clone

เหลือ: รัน migration แรกบนเครื่อง dev (DEVELOPMENT.md §3) และ deploy หน้า health check ขึ้น Vercel (§8) แล้วเปลี่ยนเป็น ✅

### F1.2 Authentication ⬜

- สมัครด้วยอีเมล รหัสผ่าน ชื่อที่แสดง
- เข้าสู่ระบบ ออกจากระบบ
- เปิดแอปใหม่แล้วยังอยู่ในระบบ (refresh token)
- route ที่ต้อง login จะพาไปหน้า login แล้วกลับมาหน้าเดิมหลังเข้าสู่ระบบ

เกณฑ์: รหัสผ่านถูก hash, login ผิดไม่บอกว่าผิดที่ช่องไหน, มี rate limit, token หมดอายุแล้วต่ออายุเองโดยผู้ใช้ไม่รู้สึก

### F1.3 Trip CRUD ⬜

- สร้างทริป: ชื่อ ปลายทาง วันเริ่ม วันจบ บังคับ / ต้นทาง งบ จำนวนคน เลือกใส่
- จำนวนคนเป็นปุ่ม +/− ระบบสร้าง guest member ให้ตามจำนวน ตั้งชื่อเริ่มต้นและแก้ได้ทันที
- ดู แก้ไข ลบ (ยืนยันก่อน)
- เปลี่ยนสถานะ: เริ่มทริป จบทริป

เกณฑ์: วันจบก่อนวันเริ่มไม่ได้, คนที่ไม่ใช่สมาชิกเข้า URL ของทริปแล้วเจอหน้า "ไม่พบทริป"

### F1.4 Dashboard ⬜

- แสดงทริปแบ่งกลุ่ม: กำลังเดินทาง, กำลังจะถึง, ที่ผ่านมา
- การ์ดทริปแสดงชื่อ ปลายทาง ช่วงวัน และข้อมูลตามสถานะ (นับถอยหลัง / วันที่เท่าไหร่ของทริป / ยอดใช้จ่ายรวม)
- ทริปที่ active อยู่บนสุดและเด่นที่สุด
- Empty state ชวนสร้างทริปแรก

## Phase 2 — Trip Planning

### F2.1 Members ⬜

- เพิ่ม แก้ชื่อ ลบ guest member
- แสดงว่าใครคือ "ฉัน"
- ลบสมาชิกที่มีรายจ่ายไม่ได้ พร้อมอธิบายเหตุผล

### F2.2 Places ⬜

- เพิ่มสถานที่ด้วยชื่อและหมวด ที่อยู่กับโน้ตเลือกใส่
- รายการสถานที่ของทริป กรองตามหมวด
- ที่พักแสดงเด่นในหน้าภาพรวมทริป

### F2.3 Daily Itinerary ⬜

- แท็บรายวัน (Day 1, Day 2 …) เลื่อนซ้ายขวา วันปัจจุบันถูกเลือกอัตโนมัติเมื่อทริป active
- เพิ่มรายการ: ชื่อ บังคับ / เวลา สถานที่ โน้ต ค่าใช้จ่ายโดยประมาณ เลือกใส่
- พิมพ์ชื่อสถานที่ใหม่ในฟอร์มได้เลย ระบบสร้าง place ให้
- จัดลำดับด้วยการลาก หรือปุ่มขึ้น/ลง
- ติ๊กว่า "ทำแล้ว" หรือ "ข้าม"

### F2.4 Transportation ⬜

- รายการชนิดการเดินทาง: วิธีเดินทาง จาก ไป เวลาออก เวลาถึง ค่าใช้จ่ายโดยประมาณ
- แสดงในลำดับเดียวกับกิจกรรม ด้วยไอคอนและรูปแบบที่ต่างกัน

เกณฑ์รวมของ phase: วางแผนทริป 3 วันให้เสร็จได้บนมือถือโดยไม่ติดขัด, แสดงยอดประมาณการรวมต่อวันและทั้งทริปเทียบกับงบ

## Phase 3 — Expense Management

### F3.1 Quick Add Expense ⬜

Feature ที่สำคัญที่สุดของแอป ขั้นตอนเป้าหมาย:

```
แตะปุ่ม +  →  พิมพ์จำนวนเงิน  →  แตะหมวด  →  บันทึก
```

- เปิดมาแล้วโฟกัสที่ช่องจำนวนเงิน แป้นตัวเลขขึ้นทันที
- หมวดเป็นปุ่มไอคอนเรียงให้แตะ ไม่ใช่ dropdown
- คนจ่ายเป็นปุ่มชื่อ เลือกคนล่าสุดไว้ให้
- เวลาเป็นตอนนี้ แตะเพื่อแก้ได้
- รายละเอียด สถานที่ ใบเสร็จ ซ่อนอยู่ใต้ "เพิ่มรายละเอียด"
- บันทึกแล้ว sheet ปิด รายการโผล่ทันที ยอดคงเหลืออัปเดต
- เน็ตหลุด: แจ้งชัดเจน ข้อมูลที่กรอกไม่หาย กดลองใหม่ได้โดยไม่เกิดรายการซ้ำ

### F3.2 Expense History ⬜

- รายการจัดกลุ่มตามวัน แสดงยอดรวมรายวัน
- กรองตามหมวดและคนจ่าย
- แตะเพื่อแก้ไข ลบได้พร้อมยืนยัน

### F3.3 Budget & Summary ⬜

- แถบงบ: ใช้ไป / คงเหลือ / เปอร์เซ็นต์ เปลี่ยนสีเมื่อเกิน 80% และเมื่อเกินงบ
- สัดส่วนตามหมวด
- ยอดรายวัน
- เฉลี่ยต่อคน

### F3.4 Who Paid & Settlement ⬜

- แต่ละคนจ่ายไปเท่าไหร่ ส่วนที่ควรจ่ายเท่าไหร่
- สรุปเป็นประโยค เช่น "เพื่อน ต้องจ่ายคืน Dxvv 625 บาท"
- หารเท่าทุกคนทุกรายการ (ข้อจำกัดของ MVP ระบุไว้ในหน้าจอ)

### F3.5 Receipt Photo ⬜

- แนบรูปใบเสร็จจากกล้องหรือคลังภาพ
- อัปโหลดหลังบันทึกรายจ่าย ไม่ขวางการบันทึกตัวเลข

เกณฑ์รวมของ phase: ยอดทุกจุดในแอปตรงกัน, ตัวเลขคำนวณที่ server, test ครอบคลุม summary และ settlement รวมกรณีเศษสตางค์

## Phase 4 — Travel Journal

### F4.1 Trip Mode ⬜

เมื่อทริปมีสถานะ `active` หน้าหลักของทริปเปลี่ยนเป็นโหมดเดินทาง

- ส่วนบน: วันที่เท่าไหร่ของทริป, งบคงเหลือ, รายการถัดไปในแผนวันนี้
- ปุ่มลัดขนาดใหญ่: **จ่ายเงิน · เช็กอิน · ถ่ายรูป · จดโน้ต**
- ส่วนล่าง: เหตุการณ์ล่าสุดของวันนี้
- ทุกอย่างที่บันทึกมี timestamp อัตโนมัติ

### F4.2 Journal Entry ⬜

- หนึ่ง entry คือหนึ่ง "ช่วงเวลา" มีส่วนประกอบเลือกได้: ข้อความ สถานที่ รูป คะแนน 1–5
- เช็กอิน: เลือกจากสถานที่ในแผน หรือพิมพ์ชื่อใหม่ หรือใช้ตำแหน่งปัจจุบัน (ขอสิทธิ์เมื่อกดใช้ครั้งแรกเท่านั้น)
- ติ๊ก "ทำแล้ว" ในแผน แล้วมีปุ่มเสนอสร้างเช็กอินให้ในแตะเดียว
- ผูกรายจ่ายเข้ากับ entry ได้
- แก้ไขและลบได้

### F4.3 Photos ⬜

- แนบหลายรูปต่อ entry
- ย่อรูปฝั่ง client ก่อนส่งเพื่อประหยัดเน็ต
- แสดง thumbnail ก่อน แตะเพื่อดูเต็ม
- แกลเลอรีรวมของทริป

### F4.4 Timeline ⬜

- รวม entry และรายจ่ายเรียงตามเวลา จัดกลุ่มรายวัน
- รูปแบบการ์ดตามตัวอย่างใน requirement: สถานที่ เวลา ข้อความ รูป รายจ่าย คะแนน
- รายจ่ายที่ไม่ได้ผูกกับ entry แสดงเป็นแถวเล็ก ไม่แย่งความเด่น

### F4.5 Trip Summary ⬜

หน้าสรุปเมื่อทริปจบ

- ค่าใช้จ่ายรวม, เฉลี่ยต่อคน, การใช้งบ
- จำนวนรายจ่าย, สัดส่วนตามหมวด
- ยอดที่ต้องเคลียร์กัน
- สถานที่ที่ไป
- จำนวนบันทึกและรูป พร้อมรูปเด่น
- ลิงก์ไป Timeline เต็ม
